# [공지] 충전중(stat=3) 충전기 `available_prob` 산출 방식 변경 (2026-08-12 적용)

> 백엔드 전달용 초안. 응답 스키마는 바뀌지 않았고, **값의 분포가 바뀝니다.**

## 한 줄 요약

충전중인 충전기의 `available_prob` 계산에서 **잔여시간 추정 성분을 뺐습니다.**
이제 ML 모델 출력이 그대로 나갑니다. 필드는 하나도 사라지지 않았습니다.

## 무엇이 바뀌나

기존에는 충전중(stat=3) 충전기만 두 값을 섞어서 내보냈습니다.

```
(변경 전)  available_prob = 0.25 × 모델확률 + 0.75 × 잔여시간점수
(변경 후)  available_prob = 모델확률
```

대기중(stat=2) 충전기는 **아무 변화가 없습니다.** 변경 대상은 충전중인
충전기뿐입니다.

## 왜 바꿨나

잔여시간 점수가 실제와 크게 어긋나 모델 예측을 망가뜨리고 있었습니다.

수집 시작일(2026-07-22)부터 08-12까지 6개 구간으로 나눠, 각 구간마다 그 이전
데이터로만 모델을 새로 학습해 검증했습니다. **18개 조합(6구간 × ETA 3종) 중
17개에서 "잔여시간 성분 비중 0"이 최적**이었습니다.

예측 오차(Brier, 낮을수록 정확):

| ETA | 변경 전 | 변경 후 | |
|---|---|---|---|
| 10분 | 0.1200 | **0.1093** | −9% |
| 20분 | 0.2226 | **0.1814** | −19% |
| 30분 | 0.3294 | **0.2149** | −35% |

특히 ETA가 길수록 심했습니다. ETA 30분에서 변경 전에는 **평균 79% 가용**이라고
답했는데 실제 가용률은 **47%** 였습니다. 변경 후에는 예측 47~48% / 실제 47~48%
로 맞습니다.

적용 직전 실제 운영 응답에서도 이런 사례가 있었습니다.

| 모델이 본 확률 | 실제로 나가던 값 |
|---|---|
| 0.4499 | **0.8625** |
| 0.3461 | **0.8356** |

## 백엔드에서 확인해 주실 것

**응답 스키마는 그대로입니다. 코드 수정은 필요 없습니다.** 다만 아래 한 가지만
봐 주세요.

**`available_prob` 에 임계값을 걸어 필터링하고 계신다면** (예: `rank_threshold`
0.5, 또는 자체 기준) **충전중 충전기가 이전보다 많이 걸러집니다.** 위 예시처럼
0.86으로 통과하던 충전기가 이제 0.45로 나가기 때문입니다.

그게 의도한 교정입니다 — 이전 값이 실제보다 과하게 높았습니다. 다만 노출되는
충전기 수가 눈에 띄게 줄 수 있으니, 임계값을 그대로 둘지 한 번 봐 주시면
좋겠습니다.

## 계속 나가는 필드 (변경 없음)

아래 세 필드는 **그대로 응답에 포함됩니다.** 값이 틀렸던 게 아니라 점수에
실린 비중이 과했던 것이라, 화면 표시용으로는 계속 쓰실 수 있습니다.

| 필드 | 설명 |
|---|---|
| `pred_remaining_min` | 예상 잔여 충전시간(분) |
| `free_by_eta_score` | 도착 전 비워질 가능성 점수 |
| `meta.remaining_model` | 잔여시간 모델 사용 여부 |

**다만 `pred_remaining_min` 을 화면에 그대로 쓰실 계획이라면 미리 알려주세요.**
이 값은 점추정이라 실제 분포와 차이가 큽니다. 실측으로 경과 30분 시점의 잔여
시간은 중앙값 15분 / 평균 71분인데, 모델은 경과와 거의 무관하게 10~25분을
내놓습니다. "약 15분 후 종료 예정" 같은 확정적 문구로는 부적절합니다.

`meta.remaining_model` 의 의미도 바뀌었습니다. 기존 안내에는 "`false`면 충전중
충전기 점수가 달라진 상태"라고 돼 있었는데, 이제 **점수에는 영향이 없고** 위
표시용 두 필드만 폴백값으로 바뀝니다.
